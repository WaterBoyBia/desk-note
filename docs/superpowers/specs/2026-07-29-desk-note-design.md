# desk-note 设计方案

## 1. 文档信息

- 项目：desk-note Windows 桌面待办程序
- 日期：2026-07-29
- 状态：设计已通过逐节确认，等待书面方案复核
- 目标平台：Windows 10、Windows 11（首版仅发布 x64）
- 技术基线：.NET 10 LTS、C#、WPF

## 2. 产品定位

desk-note 是一个轻量、离线、常驻桌面的待办便签。程序以小窗口形式展示多条待办，可选择窗口置顶；关闭主窗口时不退出，而是隐藏到系统托盘。用户可通过托盘重新显示窗口、快速新建待办或彻底退出程序。

首版强调三个目标：

1. 打开后立即看到未完成事项，创建和完成操作足够直接。
2. 所有数据保存在本地，用户可更改数据目录，迁移失败时不丢失旧数据。
3. 空闲时不轮询、不持续访问磁盘，让 CPU 和内存占用保持较低。

## 3. 首版范围

### 3.1 包含的功能

- 创建、查看、编辑和删除多条待办。
- 待办字段包括标题、备注、创建时间、更新时间、完成状态和完成时间。
- 未完成列表支持按创建时间从新到旧或从旧到新排序。
- 点击待办前的圆形勾选区完成待办，并将其移入“已完成待办”。
- 已完成待办支持恢复为未完成、单条删除和确认后全部清空。
- 浅色、深色两种主题，可即时切换并持久化。
- 可切换窗口置顶状态，并保存窗口位置、尺寸与置顶偏好。
- 关闭主窗口时隐藏到托盘；托盘菜单提供显示、快速新建和退出。
- 支持当前用户级别的开机自启动，不要求管理员权限。
- 设置中显示并允许更改数据目录；更改时自动迁移并保留备份。
- 保持单实例；重复启动只唤醒已有窗口。

### 3.2 首版不包含的功能

- 截止时间、提醒和 Windows 通知。
- 优先级、标签、搜索和复杂筛选。
- 账户、云同步、多人协作和跨设备同步。
- 移动端、Web 端或跨平台桌面端。
- 插件、脚本扩展和自动更新服务。

这些能力可在后续版本评估，但首版数据和模块边界会为扩展保留空间，不提前实现范围外功能。

## 4. 技术路线与取舍

采用 WPF + MVVM + SQLite：

- WPF 直接使用 Windows 桌面能力，不需要捆绑 Web 运行时。
- `CommunityToolkit.Mvvm` 提供可观察属性和命令，减少重复代码。
- `Microsoft.Data.Sqlite` 负责待办持久化，以事务保证单次操作的一致性。
- 设置使用 JSON，便于读取、诊断和备份，并通过临时文件替换实现原子保存。
- 托盘优先使用系统自带的 `System.Windows.Forms.NotifyIcon`，避免仅为托盘再引入第三方库。

未选择纯 JSON 待办存储，是因为每次修改都可能重写完整文件，异常退出时的恢复能力较弱。未选择 EF Core 和完整宿主框架，是因为首版业务简单，这些依赖会增加启动、包体和维护成本。

## 5. 总体架构

程序是单进程、事件驱动的桌面应用，逻辑上分为四层。逻辑分层不强制拆成多个程序集，首版优先保持工程简洁。

### 5.1 界面层

主要组件：

- `MainWindow`：主窗口、标题栏、悬停侧边栏、页面承载区。
- `TodoEditorView`：创建和编辑待办。
- `IncompleteTodosView`：未完成列表。
- `CompletedTodosView`：已完成列表。
- `SettingsView`：自启动、主题、置顶和数据位置设置。
- `TrayIconController`：托盘图标和菜单入口。

界面层只负责显示、交互和数据绑定，不直接读写文件、数据库或注册表。

### 5.2 表现逻辑层

主要 ViewModel：

- `MainViewModel`：导航、当前页面和窗口级状态。
- `TodoEditorViewModel`：输入校验、保存和取消。
- `TodoListViewModel`：列表加载、排序、完成、恢复和删除。
- `SettingsViewModel`：设置变更、错误提示和数据迁移进度。

ViewModel 通过命令调用服务接口。耗时操作使用异步方法，并在执行期间禁用重复操作。

### 5.3 应用服务层

主要服务：

- `TodoService`：待办校验、创建、编辑、状态转换、删除和排序规则。
- `SettingsService`：设置加载、校验和原子保存。
- `DataMigrationService`：数据目录检查、备份、复制、校验、切换和回滚。
- `ThemeService`：浅色/深色资源切换。
- `StartupService`：当前用户开机自启动。
- `SingleInstanceService`：单实例锁定和已有窗口唤醒。
- `WindowStateService`：窗口位置、尺寸与置顶状态恢复。

### 5.4 基础设施层

主要实现：

- `SqliteTodoRepository`：待办表结构和 CRUD。
- `JsonSettingsStore`：设置文件读取及原子替换。
- `JsonDataLocator`：读取和切换当前数据目录。
- `FileBackupStore`：迁移及数据库升级前的备份。
- `RegistryStartupService`：读写当前用户的 Windows 启动项。
- `RollingFileLogger`：记录有限的本地错误信息。

界面到数据的调用方向固定为：View → ViewModel → Service → Repository/Store。下层不依赖上层，业务逻辑可在不启动 WPF 的情况下测试。

## 6. 界面与交互设计

### 6.1 窗口形态

- 默认窗口尺寸约为 420 × 600 逻辑像素，最小尺寸约为 360 × 480。
- 窗口支持移动和缩放；关闭前保存最后一次有效的位置、尺寸和显示器信息。
- 恢复窗口时校验其是否仍处于可见显示区域。显示器拔出或分辨率改变后，将窗口调整回主显示器工作区。
- 置顶是可切换状态，而不是强制行为。标题栏提供快捷入口，设置页提供同一选项。
- 标题栏关闭按钮默认隐藏窗口到托盘，不终止进程。只有托盘菜单中的“退出”会关闭数据库并结束程序。

### 6.2 侧边栏

侧边栏按以下顺序从上到下排列：

1. 创建新待办
2. 未完成待办
3. 已完成待办
4. 设置

默认状态采用图标窄栏，宽度为 58 逻辑像素。鼠标进入侧边栏，或其中任意元素获得键盘焦点时，侧边栏在约 180 ms 内展开至 150 逻辑像素，并显示完整文字。鼠标离开且焦点不在侧边栏内时收起。

展开采用宽度变化和文字淡入，不使用持续动画。系统启用“减少动态效果”时，取消或显著缩短动画。窄栏图标提供工具提示，确保只看图标时仍能理解入口。

### 6.3 创建与编辑

- 标题必填，去除首尾空白后长度为 1—200 个字符。
- 备注可选，最多 2000 个字符。
- 保存按钮在标题无效或操作执行期间禁用。
- 创建成功后跳转到未完成列表，并将新项目显示在符合当前排序的位置。
- 单击待办卡片的正文区域进入编辑；点击圆形完成区不会进入编辑。
- 编辑页提供明确的“保存”和“取消”，取消不会修改原数据。

### 6.4 未完成列表

- 每条待办显示圆形完成区、标题、单行备注摘要和创建时间。
- 列表默认按创建时间从新到旧；用户可切换为从旧到新，选择会持久化。
- 点击完成区后先提交数据库事务，提交成功后再从未完成列表移除。
- 写入失败时卡片保持未完成，显示非阻塞错误条和“重试”入口。
- 右键菜单提供编辑和删除；删除需要确认。

### 6.5 已完成列表

- 默认按完成时间从新到旧排列。
- 已完成项显示完成标记、标题和完成时间，标题使用弱化样式而不是仅依赖颜色表达状态。
- 每条记录可恢复为未完成或永久删除。
- “全部清空”必须经过确认，并明确显示将删除的项目数量。
- 恢复操作清空 `CompletedAt`，项目重新进入未完成列表。

### 6.6 设置页

设置项包括：

- 开机自启动：切换成功后立即生效。
- 颜色模式：浅色或深色，切换后整个窗口即时更新。
- 窗口置顶：与标题栏状态同步。
- 数据位置：显示规范化的绝对路径，允许选择新目录并执行安全迁移。

设置变更通常即时保存。涉及注册表或文件迁移的操作，只有外部操作成功后才更新界面中的最终状态。

### 6.7 托盘与唤醒

托盘左键单击显示或激活主窗口。右键菜单包括：

- 显示 desk-note
- 创建新待办
- 退出

用户重复启动程序时，新进程不打开第二套数据库连接，而是通知已有实例显示主窗口，然后立即退出。

## 7. 数据设计

### 7.1 待办表

SQLite 表 `Todos` 包含：

| 字段 | SQLite 类型 | 约束与含义 |
| --- | --- | --- |
| `Id` | `TEXT` | GUID 字符串，主键 |
| `Title` | `TEXT` | 非空，应用层限制 1—200 字符 |
| `Note` | `TEXT` | 可空，应用层限制最多 2000 字符 |
| `IsCompleted` | `INTEGER` | 仅允许 0 或 1 |
| `CreatedAt` | `TEXT` | UTC ISO 8601 时间，非空 |
| `UpdatedAt` | `TEXT` | UTC ISO 8601 时间，非空 |
| `CompletedAt` | `TEXT` | 可空，完成时写入 UTC 时间 |

对 `IsCompleted`、`CreatedAt` 和 `CompletedAt` 建立满足列表查询的组合索引。界面显示时再转换为本地时间，避免夏令时或时区变化破坏排序。

### 7.2 设置模型

`settings.json` 包含：

- `schemaVersion`
- `theme`：`light` 或 `dark`
- `startWithWindows`
- `alwaysOnTop`
- `windowBounds`：左、上、宽、高和显示器标识
- `incompleteSortDirection`：`newestFirst` 或 `oldestFirst`

数据目录不重复写入 `settings.json`，而是由定位文件作为唯一真实来源，避免迁移时两个路径不一致。

### 7.3 数据目录

默认数据目录为 `%LocalAppData%\desk-note\data`，结构如下：

```text
data/
├── todos.db
├── settings.json
├── backups/
└── logs/
    └── app.log
```

`%LocalAppData%\desk-note\locator.json` 只保存当前数据目录的规范化绝对路径。该文件无法随数据目录一起移动，否则程序重启后无法定位新目录。用户可配置的数据，包括待办、设置、备份和日志，全部位于所选数据目录中。

日志采用滚动策略并限制总大小。日志记录异常类型、操作阶段和时间，不记录待办标题或备注正文。

## 8. 关键数据流

### 8.1 程序启动

1. 创建命名互斥体，确认当前进程是否为首个实例。
2. 若已有实例，通过命名管道发送“显示窗口”请求，然后退出。
3. 读取 `locator.json`；不存在时使用默认数据目录并创建定位文件。
4. 加载并校验 `settings.json`。
5. 打开 SQLite，执行必要的数据库版本迁移和快速完整性检查。
6. 加载未完成待办、恢复主题和窗口状态。
7. 创建托盘图标并显示主窗口。

### 8.2 创建或编辑待办

1. ViewModel 对标题和备注进行即时校验。
2. 用户保存后，ViewModel 调用 `TodoService`。
3. 服务规范化文本、生成时间戳，并调用仓储。
4. 仓储在事务中写入 SQLite。
5. 事务提交成功后更新内存列表和界面。
6. 失败时保持编辑内容，显示可重试错误，不伪造成功状态。

### 8.3 完成或恢复待办

1. 命令执行期间禁用该条记录的重复操作。
2. 服务检查记录当前状态，避免重复完成或恢复。
3. 完成时设置 `IsCompleted = 1` 和 `CompletedAt`；恢复时设置 `IsCompleted = 0` 并清空 `CompletedAt`。
4. 数据库事务提交后，在两个列表之间移动记录。
5. 失败时保留原列表和原状态。

### 8.4 更改数据目录

迁移遵循“旧位置在切换成功前始终可用”的原则：

1. 将用户选择的目录转为规范化绝对路径。如果它与当前目录相同则直接结束；否则检查其不是当前数据文件的子文件路径，并验证读写权限与可用空间。
2. 暂停新的写操作，等待正在执行的数据库操作完成。
3. 关闭当前 SQLite 连接，在旧数据目录的 `backups` 中生成带时间戳的备份。
4. 将数据库、设置、已有备份和日志复制到新目录下的临时迁移子目录。
5. 对复制后的数据库执行 `PRAGMA integrity_check`，并重新读取设置文件确认格式有效。
6. 在新位置原子重命名临时目录，使其成为正式数据目录。
7. 通过临时文件替换原子更新 `locator.json`。
8. 从新位置重新打开 SQLite 并读取一遍核心设置。
9. 全部成功后恢复写操作，并将旧位置保留为可恢复备份。

如果第 7 步之前失败，定位文件不变，程序直接重新打开旧位置。如果更新定位文件后重新打开失败，程序将定位文件回滚到旧路径并重新打开旧数据库。界面显示失败阶段和旧数据位置，但不删除任何旧文件。

## 9. Windows 集成

### 9.1 开机自启动

使用当前用户注册表项 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，不请求管理员权限。启用时写入已安装的可执行文件路径，禁用时移除对应项。

`settings.json` 中的 `startWithWindows` 表示用户期望状态，注册表项表示系统实际状态。用户切换时先修改并验证注册表，再保存设置；任一步失败时回滚到原状态。程序启动时核对两者：如果用户期望启用而路径因升级发生变化，只把同名 desk-note 启动项修正为当前已安装程序；修正失败时保留设置并显示“自启动未生效”警告。如果用户期望禁用，则移除同名启动项。

### 9.2 单实例

使用命名互斥体控制单实例，并使用仅限当前用户会话的命名管道传递唤醒命令。管道只处理预定义命令，不接受任意文件路径或脚本内容。

### 9.3 托盘生命周期

主窗口隐藏后程序保持事件循环，但不运行定时刷新任务。托盘“退出”执行有序关闭：停止接收新命令、等待当前写入结束、释放数据库和托盘资源，再退出进程。

## 10. 错误处理与恢复

### 10.1 设置文件异常

- JSON 不存在：创建默认设置。
- JSON 字段缺失：按字段补充默认值。
- JSON 无法解析：将原文件重命名为带时间戳的损坏副本，使用默认设置启动，并提示副本位置。
- 保存失败：保留内存中的旧设置值，显示错误，不覆盖原文件。

### 10.2 数据库异常

- 打开失败或完整性检查失败时，停止写入并展示恢复界面。
- 恢复界面列出最近备份、当前数据位置和“重试打开”入口。
- 程序不自动用备份覆盖当前数据库；恢复操作需要用户明确确认。
- 数据库结构升级前必须先创建备份，迁移在事务中完成。

### 10.3 普通写入失败

- 界面只在事务提交后反映最终状态。
- 错误提示采用窗口内错误条，不弹出大量模态对话框。
- 删除、全部清空和数据恢复等不可逆操作必须确认。
- 磁盘空间不足、路径只读和文件被占用均提供可理解的中文提示。

## 11. 资源占用策略

- 不创建后台 Web 服务，不嵌入浏览器运行时。
- 不使用定时器轮询数据库或文件系统；数据只在启动和用户操作时读写。
- 列表采用 WPF UI 虚拟化，避免待办数量增加时创建过多可视元素。
- SQLite 连接按明确生命周期管理，写入使用短事务。
- 主题资源在应用级复用，不为每个卡片重复创建大型对象。
- 日志异步、限量写入，不记录高频无价值事件。
- 主窗口隐藏到托盘后释放不再使用的页面资源，但保留必要 ViewModel 和数据库服务。

首版使用一个 WPF 应用项目和一个测试项目，以目录与接口体现模块边界：

│       ├── Models/
│       ├── Views/
│       ├── ViewModels/

│       ├── Infrastructure/

当核心业务明显增长，或需要独立复用时，再将领域逻辑和基础设施拆成单独程序集。首版不为尚未出现的复用需求增加项目数量。

## 13. 测试设计

### 13.1 单元测试

- 标题去除首尾空白、空标题拒绝、长度边界。
- 备注长度边界。
- 创建、编辑、完成、恢复、删除和全部清空的业务规则。
- 未完成与已完成列表的排序规则。
- ViewModel 命令的可执行状态、成功状态和错误状态。
- 设置默认值、字段补全、主题切换和窗口状态校验。
- 自启动切换失败时的状态回滚。

### 13.2 SQLite 与文件集成测试

- 首次建库和结构版本升级。
- 创建、更新、完成、恢复、删除后重新打开数据库，数据保持一致。
- 事务失败后没有部分写入。
- 非法设置 JSON 的隔离与默认设置恢复。
- 设置文件临时写入和原子替换。
- 数据目录迁移成功路径。
- 新目录不可写、复制失败、校验失败、定位文件更新失败和重新打开失败时的回滚。
- 包含中文、空格和较长路径的数据目录。

文件测试只使用测试运行创建的临时目录，不读写用户真实数据目录和真实注册表启动项。Windows 集成通过接口替身进行自动化测试。

### 13.3 Windows 手工验收

- Windows 10 和 Windows 11 的安装、启动、退出与卸载。
- 100%、125%、150% 和 200% DPI 下的文字、侧边栏和窗口缩放。
- 多显示器下保存位置，以及移除副显示器后的窗口恢复。
- 托盘显示、快速新建、隐藏和显式退出。
- 开机自启动启用、禁用和重启验证。
- 置顶开关、浅色/深色主题和键盘导航。
- 数据目录迁移到普通目录、中文目录、只读目录和空间不足的磁盘。
- 异常终止后重新启动，确认待办和设置仍可读取。

## 14. 性能与质量验收标准

在发布候选版本和固定测试机器上记录环境后验收：

- 空闲 60 秒平均 CPU 使用率不高于 0.5%，且没有持续数据库或日志写入。
- 加载 1000 条待办后，进程专用工作集目标不高于 120 MB。
- 冷启动到主窗口可操作的目标时间不高于 1.5 秒。
- 创建、完成、恢复和编辑待办后立即重启，数据结果与界面最后确认的状态一致。
- 数据目录迁移的每个可模拟失败点都能回到旧路径，旧数据库仍可打开。
- 自动化测试全部通过，Windows 10/11 手工验收清单没有阻断问题。
- 空列表、长标题、长备注、1000 条列表和数据异常状态都有清晰界面。

性能数值是首版工程目标。如果固定测试机器的硬件或安全软件使冷启动目标不可比较，应保留原始测量并单独解释，但不能取消空闲无轮询和无持续磁盘写入的要求。

## 15. 发布方式

- 首版发布 `win-x64` 自包含安装包，用户无需预装 .NET。
- 安装范围默认为当前用户，普通使用、自启动和数据目录迁移均不要求管理员权限。
- 安装目录与用户数据目录分离；卸载程序默认不删除用户数据。
- 卸载时如提供“同时删除用户数据”选项，必须默认不勾选，并明确显示目标数据目录。

## 16. 已确认的关键决策

- 产品形态：桌面便签 + 系统托盘。
- 窗口行为：普通便签窗口，可选择置顶。
- 侧边栏：默认图标窄栏，悬停或键盘聚焦时展开完整文字栏。
- 技术栈：C# + WPF，采用 MVVM。
- 存储：待办使用 SQLite，设置使用 JSON。
- 首版待办范围：标题、备注、创建时间、完成状态和基础排序。
- 已完成操作：查看、恢复、单条删除和全部清空。
- 数据位置变更：自动迁移、完整性校验、保留备份、失败回滚。
- 资源策略：单进程、事件驱动、无后台轮询。
