# desk-note 图标、紫色玻璃主题与窗口透明度设计

## 1. 文档信息

- 项目：desk-note Windows 桌面待办程序
- 日期：2026-07-31
- 状态：设计已通过用户确认和独立规格审查
- 适用平台：Windows 10、Windows 11
- 技术基线：.NET 10、C#、WPF、MVVM
- 上位设计：`docs/superpowers/specs/2026-07-29-desk-note-design.md`

## 2. 目标与已确认决策

本次改进只调整程序的视觉体系、图标接入和窗口透明度，不改变待办业务、数据目录、托盘生命周期及导航结构。

已确认的设计决策如下：

1. 使用 `icon/icon.png` 作为程序图标的唯一源图，覆盖 EXE、主窗口、任务栏、系统托盘、Inno Setup 安装包和卸载项。
2. 浅色模式使用浅紫色与白色；深色模式使用深紫色与黑色。
3. 深色模式的文字统一使用白色色相，通过不透明度区分主次，不再使用灰色或紫色文字。
4. 移除窗口和按钮的黑色描边，以半透明高光、主题色细边、层级背景和柔和阴影表达边界。
5. 按钮及同类可交互控件使用圆弧边角，并具备玻璃质感的默认、悬停、按下、聚焦和禁用状态。
6. 玻璃路线采用已选择的 B 方案：Windows 11 优先使用原生 Mica；Windows 10、低于 100% 的整窗透明度以及原生效果不可用时，使用 WPF 内部实现的紫色半透明 Acrylic 风格磨砂背景。
7. 设置页增加“窗口透明度”，范围为 20%—100%，默认 100%。透明度作用于整个主窗口，包括文字、图标和按钮；拖动时实时预览并自动保存。

## 3. 非目标

本次不实现以下内容：

- 不重新设计侧边栏布局；继续保持默认 58 像素窄栏、悬停或键盘聚焦时展开到 150 像素。
- 不增加自定义主题色选择器、壁纸取色、动态背景或跟随系统主题。
- 不为不同页面保存独立透明度，也不让托盘菜单或恢复窗口共享主窗口的透明度值。
- 不实现鼠标穿透、点击穿透、窗口模糊强度调节或隐藏窗口控件。
- 不引入 Windows App SDK，只为视觉效果增加体积较大的 UI 框架。
- 不改变 SQLite 数据结构。

## 4. 视觉语言

### 4.1 浅色主题

浅色主题以白色为主要内容底色，以低饱和浅紫色表达品牌和层级。建议资源基准如下，最终可在实现时根据真实窗口截图做小幅校准：

| 用途 | 建议颜色或表现 |
| --- | --- |
| 窗口后备底色 | `#F6F0FF` |
| 内容玻璃层 | 白色，约 70%—85% 不透明度 |
| 侧边栏 | `#DCC6FF`，带纵向透明渐变 |
| 主强调色 | `#7A3FAE` |
| 主文字 | `#332440` |
| 次要文字 | `#705F7D` |
| 玻璃高光边 | 白色，约 55%—75% 不透明度 |
| 危险操作 | 深玫紫背景或图标，保证文字对比度 |

窗口、卡片和按钮不使用纯黑描边。边界由浅色高光、紫色透明阴影和相邻层的明度差共同表达。

### 4.2 深色主题

深色主题以接近黑色的窗口背景配合深紫层级，避免现有深灰配色。建议资源基准如下：

| 用途 | 建议颜色或表现 |
| --- | --- |
| 窗口后备底色 | `#07040B` |
| 内容玻璃层 | `#160B1F`，约 75%—88% 不透明度 |
| 侧边栏 | `#3A165A`，向 `#1B092A` 渐变 |
| 主强调色 | `#AE73E6` |
| 主文字 | `#FFFFFF` |
| 次要文字 | 白色，约 68%—76% 不透明度 |
| 禁用文字 | 白色，约 38%—46% 不透明度 |
| 玻璃高光边 | 白色或浅紫色，约 10%—22% 不透明度 |

“所有文字为白色”指所有文本前景均使用白色色相；主次信息只通过透明度、字重和字号区分。错误提示使用深红紫或玫紫背景配白字，不能恢复为红色文字或灰色文字。

### 4.3 圆角与层级

- 主窗口在 Windows 11 上请求系统圆角；内部根容器使用约 18 像素圆角。
- 内容卡片使用约 12—16 像素圆角。
- 普通按钮使用约 10—12 像素圆角；紧凑图标按钮使用约 9—11 像素圆角。
- 输入框、列表项、复选框承载区和设置分组复用同一圆角尺度，不出现一部分直角、一部分圆角的混杂状态。
- 阴影保持柔和且透明，不使用黑色硬阴影。深色模式允许使用黑色环境阴影，但它不能形成清晰黑色描边。

## 5. 原生玻璃与兼容降级

### 5.1 原生材料策略

新增窗口外观服务，在窗口句柄创建后尝试通过 DWM 能力启用系统背板，并同步浅色/深色模式：

- Windows 11 支持 `DWMWA_SYSTEMBACKDROP_TYPE` 时，主窗口优先使用适合长驻窗口的 Mica 系统背板。
- 同步设置沉浸式深色模式和系统圆角偏好，主题切换后重新应用相关属性。
- 原生调用必须封装在独立服务中，返回成功或失败，不让平台异常传播到应用启动流程。
- 不设置 `AllowsTransparency="True"`，避免破坏窗口硬件合成、缩放和 DWM 背板能力。

设置页、待办卡片和按钮不是独立顶层窗口，使用 WPF 半透明画刷、渐变、高光边和阴影形成与系统背板一致的玻璃层次。

窗口材料只有两个明确状态：

- `NativeMica`：仅在 Windows 11、窗口透明度等于 100%、DWM 组合已启用且所有原生调用成功时进入。根背景切换为透明的 `NativeBackdropOverlayBrush`，只保留轻微紫色染色和高光，不能用不透明后备底色盖住 Mica。
- `FallbackGlass`：其它所有情况进入。根背景切换为可独立保证可读性的 `FallbackWindowBrush`，不依赖桌面内容或 DWM 背板提供对比度。

状态由窗口外观服务计算并返回，主窗口只根据返回状态选择对应资源。触发重新计算的时机包括：窗口 `SourceInitialized`、主题切换、透明度跨入或离开 100%、窗口重新显示，以及收到 `WM_DWMCOMPOSITIONCHANGED` 或主题/颜色设置变化消息。离开 `NativeMica` 时先恢复后备背景，再关闭系统背板；进入 `NativeMica` 时先成功启用背板，再切换透明覆盖层，避免中间帧出现不可读的透明窗口。

### 5.2 降级规则

以下任一情况出现时，程序继续正常运行，并进入 `FallbackGlass`，使用主题资源中的紫色磨砂后备背景：

- Windows 10 不提供本方案所需的受支持 Mica 背板能力。
- Windows 11 版本、远程桌面、节能策略或系统合成设置使原生背板不可用。
- 整窗透明度低于 100%，无论当前系统是否可能继续绘制 Mica。
- DWM 调用返回失败或窗口句柄尚不可用。

功能优先级固定为：窗口可操作与透明度设置 > 主题可读性 > 原生背板。原生效果失败不能阻止主窗口显示，也不能弹出错误对话框；必要时只写入现有本地错误日志。

本方案不在 Windows 10 调用未公开的 Acrylic 接口；Windows 10 的 Acrylic 观感完全由 WPF 后备画刷实现。

### 5.3 窗口结构

- 主窗口继续使用无系统标题栏的 `WindowStyle="None"` 和 `WindowChrome`。
- 移除当前根 `Border` 的黑色或实色外框，根容器边缘改为透明高光层。
- 保留不可见的缩放命中区域，不能因移除可见边框而破坏窗口缩放。
- 标题栏、侧边栏和内容区使用不同透明层级，但共同位于系统背板之上。
- 窗口最大化时不得在屏幕四周留下圆角缝隙或裁掉窗口按钮。

## 6. 控件样式体系

`Resources/Controls.xaml` 负责统一控件模板，主题文件只提供颜色、透明度、阴影和状态画刷。控件不能在页面内各自写死黑色边框或主题颜色。

### 6.1 按钮与标题栏控件

所有 `Button` 和 `ToggleButton` 使用圆角模板，至少包含以下状态：

- 默认：半透明主题表面、透明高光边、轻微环境阴影。
- 悬停：提高表面亮度和高光强度，不能突然出现黑色边框。
- 按下：降低表面亮度并略微减弱阴影，形成按压反馈。
- 键盘聚焦：使用紫色或白色的清晰聚焦环，聚焦状态不能只靠颜色很弱的阴影表示。
- 禁用：降低整体对比度，仍保持文字可辨识。
- 置顶切换选中：使用主强调色玻璃层，并保持与标题栏其它按钮相同的尺寸和圆角。

标题栏的最小化、最大化和隐藏按钮使用专用紧凑样式，但复用同一状态资源。关闭/隐藏按钮只有悬停或按下时使用危险操作背景，默认状态不显示红色块。

### 6.2 文本、输入和选择控件

- `Window`、`UserControl`、`TextBlock`、`TextBox`、`CheckBox`、`ListBoxItem` 和按钮内容必须从主题资源继承前景色。
- 自定义 `TextBox` 模板移除系统黑边，使用圆角玻璃底、透明高光边和明确的键盘聚焦环。
- `CheckBox` 的方框、勾选标记和标签均使用主题资源；深色模式标签和勾选标记为白色。
- `ListBox` 保持虚拟化，样式改动不能替换为破坏虚拟化的外层容器。
- 滚动条、进度条及菜单若出现系统默认黑色边框，应提供轻量主题样式；不得为了视觉统一关闭键盘操作或自动化可访问名称。

透明度 `Slider` 必须使用专用玻璃模板，不能保留系统默认轨道：未填充轨道使用半透明主题表面，已填充轨道使用主强调色，圆形滑块使用白色或浅紫高光并带柔和阴影。鼠标悬停时提高滑块高光，按下时缩小阴影，键盘聚焦时显示清晰聚焦环，禁用时降低整体不透明度。轨道、滑块和聚焦环均不得出现黑色描边；方向键仍能按 1% 步进调整。

### 6.3 页面层次

待办卡片、编辑表单、设置分组和数据恢复窗口使用相同的玻璃资源。主窗口与恢复窗口都显示统一图标和主题，但恢复窗口不应用用户设置的主窗口透明度，避免在故障恢复场景中降低可读性。

## 7. 窗口透明度

### 7.1 设置模型

在 `AppSettings` 增加 `WindowOpacity`，类型为 `double`：

- 合法范围：`0.20`—`1.00`。
- 默认值：`1.00`。
- 旧设置文件缺少该字段时自动使用 `1.00`，不要求数据库迁移。
- 加载后对越界数值进行限制；不可解析的 JSON 继续沿用现有损坏文件隔离策略。
- `SettingsService` 的克隆与回滚必须包含该字段，避免保存失败时丢失原值。

### 7.2 设置页交互

设置页增加带文本标签的滑块：

- 标签为“窗口透明度”，右侧显示当前百分比整数。
- `Minimum=0.20`、`Maximum=1.00`，建议步进为 `0.01`。
- 滑块改变时，主窗口 `Opacity` 通过绑定立即更新，因此文字、图标、按钮和背景同时变化。
- 最新值在停止连续拖动约 250—350 ms 后自动写入 `settings.json`，避免每移动一个百分点都写磁盘。
- 新变更到来时只取消仍处于防抖等待阶段的旧请求；一旦进入 `SettingsService.UpdateAsync`，该写入不再被滑块的取消令牌中止。这不是后台轮询，也不会改变空闲资源策略。
- 每次透明度变更携带单调递增的版本号。任何版本保存成功后都更新“最后持久化值”，因为它代表磁盘真实状态；旧版本成功时不能把该值回写到 ViewModel 并覆盖较新的预览。只有当前最新版本保存失败时，才把界面恢复到当时最新的“最后持久化值”，并展示中文错误“无法保存窗口透明度。”。
- 透明度低于 40% 时显示非阻塞说明，提示文字和控件可能较难辨认，但不能擅自把用户选择抬高到 40%。

窗口首次创建时立即从设置应用透明度。隐藏到托盘再显示、单实例唤醒和主题切换不得重置该值。

### 7.3 与系统背板的关系

WPF 的整窗 `Opacity` 可能改变窗口合成路径，使 Mica/Acrylic 失效。实现不承诺在所有 20%—99% 的数值下同时保留系统背板；当系统背板不可用时，主题中的紫色半透明磨砂层负责维持已确认的视觉方向。100% 时应优先恢复原生系统背板。

为消除不确定切换，实际规则固定为：`WindowOpacity < 1.00` 时主动使用 `FallbackGlass`；只有恢复到 `1.00` 后才重新尝试 `NativeMica`。

## 8. 图标资源与发布链路

### 8.1 唯一源图

`icon/icon.png` 是唯一人工维护的源图。为满足 Windows Win32 图标接口，允许从该 PNG 确定性生成多尺寸 `.ico` 派生产物，但不得另行设计或手工修改第二套图标。

派生 `.ico` 至少包含常用的 16、20、24、32、40、48、64、128 和 256 像素尺寸，并保留透明通道。生成后需检查小尺寸是否清晰、边缘是否出现黑底或白边。

### 8.2 使用位置

- WPF 项目通过 `ApplicationIcon` 使用派生 `.ico`，使发布后的 EXE、资源管理器和任务栏显示新图标。
- 主窗口和恢复窗口显式使用打包资源中的图标，避免窗口未继承应用图标。
- `TrayIconController` 从应用资源加载同一派生图标，不再使用 `SystemIcons.Application`，并在释放托盘对象时正确释放图标资源。
- Inno Setup 使用派生 `.ico` 作为 `SetupIconFile`，安装后的快捷方式和卸载项继续指向带图标的 EXE。
- PNG 与派生 ICO 均随项目版本管理；发布流程不依赖开发机器上未记录的手工转换步骤。

## 9. 组件与数据流

### 9.1 主要组件变化

- `ThemeService`：切换主题资源后通知或调用窗口外观服务重新同步 DWM 深色属性和系统背板。
- `WindowBackdropService`：封装操作系统检测、DWM 调用、圆角偏好和安全降级；服务不保存用户设置。
- `AppSettings` / `SettingsService`：保存、加载、限制和回滚 `WindowOpacity`，并通过实例级异步互斥门串行化全部设置写入。
- `SettingsViewModel`：暴露可绑定透明度值、百分比文本、低透明度提示和防抖保存逻辑。
- `MainWindow`：绑定 `Opacity`，在句柄就绪、主题变化和必要的窗口状态变化后应用外观。
- `Controls.xaml` 与主题资源：提供统一玻璃控件模板及浅色、深色画刷。
- `TrayIconController`、项目文件和 Inno Setup：接入派生图标。

### 9.2 透明度变更数据流

1. 用户拖动设置页滑块。
2. `SettingsViewModel.WindowOpacity` 立即变化。
3. 主窗口绑定立即更新 `Window.Opacity`，完成整窗实时预览。
4. ViewModel 增加透明度变更版本号，取消上一笔仍在等待的防抖请求，并安排最新值。同一段连续拖动在防抖结束前只产生一次物理写入；如果旧写入已经进入服务，则允许它先完成，不能声称整个交互绝对只有一次写入。
5. 防抖结束后调用 `SettingsService.UpdateAsync`；进入服务后的保存不再被后续滑块变化取消。
6. `SettingsService` 使用一个实例级异步互斥门串行化全部设置更新。每笔更新在门内克隆最新 `Current`、应用本次字段变更、原子保存，失败时只恢复本笔快照，然后释放门。
7. 任一透明度保存成功后，ViewModel 都更新“最后持久化值”；仅当该版本仍为最新时，才需要确认当前预览与它一致。保存失败且版本仍为最新时恢复当时的“最后持久化值”并显示错误；旧版本失败不回滚新的界面值。

主题、窗口置顶、自启动、窗口位置和透明度都必须经过同一个设置更新门，禁止多个 `settings.json` 写入重叠。外部注册表操作仍遵循现有“外部操作成功后再保存设置”的顺序；设置门只保护内存设置快照和文件写入，不包围注册表或数据迁移等外部操作。

### 9.3 主题变更数据流

1. 用户选择浅色或深色。
2. 现有设置保存成功后，`ThemeService` 替换主题资源字典。
3. 所有动态资源立即更新，包括窗口、文字、输入框和按钮状态。
4. 窗口外观服务同步 DWM 深色标志并重新尝试系统背板。
5. 当前 `Window.Opacity` 保持不变。

## 10. 错误处理与安全边界

- DWM 或图标加载失败不能导致应用退出；记录错误后采用后备样式或可用的内置图标资源。
- 设置保存遵循现有原子写入和失败回滚策略，不允许界面显示已保存而磁盘仍为旧值。
- 透明度始终限制在 20%—100%，防止异常设置把窗口变为完全不可见。
- 恢复窗口保持 100% 不透明，以保证数据库故障处理可见；其颜色和控件仍使用当前主题。
- 不访问项目目录外的图标文件，不从运行时网络下载资源。

## 11. 测试与验收

### 11.1 自动化测试

- 旧 `settings.json` 不包含 `WindowOpacity` 时加载为 `1.00`。
- 透明度保存后重新加载保持一致，越界值被限制到 `0.20` 或 `1.00`。
- `SettingsService` 更新失败时，透明度随其它字段一起回滚。
- 防抖等待期内的一组连续透明度变更只持久化最后值；若较旧写入已经开始，允许中间值先写入，但全部成功完成后最终文件必须是最新值。
- 两个不同设置并发更新时通过异步互斥门串行保存，最终文件同时包含两项成功变更；其中一项失败时不会回滚另一项已经成功的变更。
- 旧透明度保存晚于新预览时，不覆盖较新的 ViewModel 值；旧保存成功仍更新磁盘基线，确保较新保存失败时回滚到磁盘真实值。
- 保存失败时 ViewModel 恢复最后成功值并显示中文错误。
- 深色资源中所有文本前景资源均为白色色相，核心控件模板显式引用主题前景资源；资源契约测试包含 `Slider` 的轨道、填充、滑块和聚焦环资源键。
- 窗口外观服务在不支持的系统版本或 DWM 返回失败时选择后备路径且不抛出启动级异常。
- 图标资源可以从程序集加载，并能转换为托盘所需的 `System.Drawing.Icon`。

### 11.2 Windows 手工验收

- Windows 11 上确认 100% 透明度时系统背板、圆角和深浅主题正确；关闭系统透明效果后程序仍可读。
- Windows 10 上确认紫色磨砂后备样式正常，无黑色外框或按钮黑边。
- 分别在 20%、40%、60%、80%、100% 检查整窗透明度，确认标题、侧边栏、内容、文字和按钮一起变化。
- 拖动滑块后重启应用，确认最后保存值恢复；快速拖动时无明显卡顿或持续磁盘写入。
- 深色模式逐页检查主窗口、设置、编辑、未完成、已完成和恢复窗口，所有文字均为白色色相。
- 用鼠标和键盘检查按钮、切换按钮、文本框、复选框、列表项的悬停、按下、聚焦和禁用状态。
- 用鼠标拖动滑块，并用 Tab、左右方向键检查 1% 步进、聚焦环、悬停、按下和禁用状态，确认不存在系统默认黑边。
- 检查窗口缩放、最大化、最小化、隐藏到托盘及侧边栏展开动画，确认玻璃模板没有破坏原行为。
- 在资源管理器、任务栏、窗口标题、托盘、安装向导、桌面快捷方式和卸载项中检查图标。
- 在 100%、125%、150% 和 200% DPI 下确认图标清晰、圆角无锯齿、文字未裁切。

## 12. 完成标准

满足以下条件后，本次视觉改进可以视为完成：

1. 所有图标位置均来自 `icon/icon.png` 的同一视觉源，不再显示系统默认应用图标。
2. 浅色和深色主题符合已确认的紫白、紫黑方向，深色所有文字使用白色色相。
3. 主窗口和控件不出现黑色硬描边，按钮具有一致圆弧和玻璃交互状态。
4. Windows 11 原生背板可用时正确启用；不可用时自动降级且不影响功能。
5. 20%—100% 整窗透明度实时生效、自动保存、重启恢复并能在失败时回滚。
6. 自动化测试通过，Windows 10/11 手工验收没有阻断问题。
