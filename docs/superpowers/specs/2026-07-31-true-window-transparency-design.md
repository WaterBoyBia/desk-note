# desk-note 真正整窗透明修复设计

## 1. 文档信息

- 日期：2026-07-31
- 状态：设计与书面方案已通过用户审查
- 适用范围：desk-note 主窗口透明度功能
- 关联计划：`docs/superpowers/plans/2026-07-31-visual-theme-implementation.md`

本文档修正原可视化计划中的窗口透明度实现。若原计划中的 Mica 行为与本文档冲突，以本文档为准。

## 2. 问题与根因

当前主窗口把 `Settings.WindowOpacity` 直接绑定到 WPF `Window.Opacity`，但没有启用 WPF 透明窗口能力。透明度低于 100% 时，程序会关闭 Mica，并在窗口下方使用完全不透明的 `FallbackWindowBrush`。最终效果是界面内容变暗，但窗口后方的桌面或其他应用没有真实透出。

诊断时在 20% 透明度下确认窗口没有分层窗口样式，也没有有效的 Win32 窗口 Alpha。因此，现有实现不满足“透过程序看到桌面”的要求。

## 3. 目标与非目标

### 3.1 目标

- 透明度范围继续为 20%—100%。
- 背景、文字、按钮、图标作为一个整体同步透明。
- 低于 100% 时能真实看到窗口后方的桌面或其他应用。
- 20% 时窗口仍可正常点击、拖动、缩放和操作，不启用鼠标穿透。
- 保留现有浅紫/白、深紫/黑、白色深色主题文字、圆角和自绘玻璃质感。
- 保留现有透明度即时预览、防抖保存、重启恢复和保存失败回滚。
- Windows 10 和 Windows 11 使用同一套稳定行为。

### 3.2 非目标

- 不实现点击穿透。
- 不增加背景模糊强度、颜色强度等新设置。
- 不修改待办数据、SQLite 结构或设置文件结构。
- 不引入 Windows App SDK、DirectComposition 或未公开 Acrylic API。
- 不在本次修复中重做现有主题和控件布局。

## 4. 方案比较与决策

### 4.1 方案 A：WPF 原生透明窗口（采用）

为主窗口启用 `AllowsTransparency=True`，保留 `WindowStyle=None`、透明窗口背景和现有整窗 `Opacity` 绑定。WPF 将窗口作为支持 Alpha 的透明窗口进行合成，透明度滑块会统一作用于整个窗口视觉树。

优点：

- 实现路径直接，符合 WPF 的透明窗口模型。
- Windows 10 和 Windows 11 行为一致。
- 不需要在拖动滑块时动态修改 Win32 窗口样式。
- 能直接满足所有内容一起透明的需求。

代价：

- 透明窗口不能继续使用原生 Mica。
- 视觉玻璃感由现有 WPF 画刷、渐变、高光和圆角承担。
- 需要验证透明窗口下的缩放、最大化、圆角和性能表现。

### 4.2 方案 B：Mica 与 Win32 分层 Alpha 动态切换（不采用）

100% 时使用 Mica；20%—99% 时动态启用 `WS_EX_LAYERED` 和窗口 Alpha。

该方案可以保留 Mica，但动态切换窗口合成模式容易引入闪烁、黑底、样式重建和窗口状态异常。外部诊断原型还出现了 Win32 错误 87，稳定性成本高于本项目收益。

### 4.3 方案 C：Acrylic 或 DirectComposition（不采用）

该方案可提供更强的模糊玻璃效果，但实现复杂、Windows 10/11 差异较大，也不能比方案 A 更直接地满足整窗统一透明需求。

## 5. 窗口渲染架构

主窗口采用以下渲染层次：

1. `Window` 使用 `WindowStyle=None`、`AllowsTransparency=True` 和透明背景。
2. `RootSurface` 继续承载窗口的主题背景、圆角、标题栏、侧边栏和页面内容。
3. `Settings.WindowOpacity` 继续绑定到 `Window.Opacity`。
4. WPF 在窗口级对完整视觉树应用 Alpha，再与桌面进行合成。

在 100% 时，`RootSurface` 使用现有主题后备画刷，窗口呈现完整的紫色玻璃外观。在 20%—99% 时，整个 `RootSurface` 及其子元素统一淡化，窗口后方内容真实可见。圆角外部区域保持完全透明。

## 6. 组件调整

### 6.1 保留的组件

- `AppSettings.WindowOpacity`：继续提供 20%—100% 范围、默认值和规范化。
- `SettingsViewModel`：继续负责即时预览、防抖持久化和失败回滚。
- `SettingsView`：继续使用现有透明度滑块和低透明度提示。
- `Light.xaml`、`Dark.xaml`、`Controls.xaml`：继续提供主题与自绘玻璃质感。

### 6.2 调整的组件

- `MainWindow.xaml`：启用 WPF 透明窗口能力，保留整窗透明度绑定。
- `MainWindow.xaml.cs`：移除 Mica 状态计算、主题和系统消息触发的背板重算，以及托盘恢复时的背板重算。
- `App.xaml.cs`：不再构造并注入 `WindowBackdropService`。
- `docs/testing/windows-acceptance.md`：用真正整窗透明验收项替换原 Mica 验收项。

### 6.3 移除的组件

- `WindowBackdropService` 及其 DWM Mica API 封装。
- 只验证 Mica 状态切换的 `WindowBackdropServiceTests`。

透明窗口与 Mica 不能共同构成本方案的有效运行路径，保留这些实现会形成不可达代码并误导后续维护。

## 7. 数据流与状态行为

透明度更新的数据流如下：

```text
设置滑块
  → SettingsViewModel.WindowOpacity
  → MainWindow.Opacity 数据绑定
  → WPF 对完整窗口视觉树应用 Alpha
  → Windows 桌面合成显示窗口后方内容
```

持久化流程保持不变：滑块变化先即时更新窗口，停止快速变化后再保存设置。保存成功后，新值成为回滚基线；保存失败时，`SettingsViewModel` 恢复最后一次成功保存的值，窗口也随绑定立即恢复。

主题切换只替换资源字典中的颜色和画刷，不修改透明度。托盘隐藏和恢复、单实例唤醒、最大化和还原也不创建新的透明度状态源。

## 8. 兼容与异常处理

- 不再调用 DWM Mica API，因此系统不支持 Mica、关闭系统透明效果或处于远程桌面时不会产生 Mica 初始化错误。
- `AllowsTransparency` 在窗口初始化前由 XAML 固定，不在运行时切换，避免窗口句柄重建和视觉闪烁。
- 20% 只是窗口视觉 Alpha，不设置 `WS_EX_TRANSPARENT`，因此不会产生鼠标穿透。
- 如果设置保存失败，继续使用现有可恢复的回滚逻辑，不增加新的错误提示机制。
- 恢复窗口不属于可调透明度主窗口，继续保持 100% 不透明。

## 9. 测试设计

### 9.1 自动化测试

先新增一个窗口透明度 XAML 契约测试，并在修改生产代码前确认失败。测试至少验证：

- 主窗口根元素设置 `AllowsTransparency=True`。
- 主窗口背景保持透明。
- `Window.Opacity` 仍绑定 `Settings.WindowOpacity`。
- `WindowStyle=None`，满足 WPF 透明窗口前置条件。

完成最小实现后运行相关契约测试、Debug 全量测试和 Release 全量测试。移除 Mica 服务时同步移除只覆盖已删除行为的测试，不降低设置持久化、主题资源和窗口透明度契约的覆盖。

### 9.2 Windows 交互验收

在隔离数据目录启动 Debug 程序，分别检查 20%、40%、60%、80%、100%：

- 低于 100% 时能看到窗口后方桌面或其他应用，不只是界面亮度下降。
- 背景、文字、按钮和图标同步透明。
- 20% 时仍可点击按钮、拖动窗口、调整尺寸和操作滑块。
- 浅色/深色切换不重置透明度。
- 隐藏到托盘后恢复、单实例唤醒、最大化和还原不重置透明度。
- 圆角外部保持透明，无黑底、黑边或明显闪烁。
- 100% 时使用现有自绘紫色玻璃背景，不再要求 Mica。

Windows 11 上完成上述验收；Windows 10 若当前没有可用环境，则明确记录为待人工验证，不伪报通过。

## 10. 完成标准

满足以下条件后，本修复任务才视为完成：

1. 新增契约测试按测试驱动流程先失败后通过。
2. Debug 和 Release 全量自动化测试通过。
3. 实际运行时，20%—99% 能真实透出窗口后方内容。
4. 透明度作用于完整窗口内容且不产生鼠标穿透。
5. 主题、托盘恢复、窗口状态和设置持久化没有回归。
6. Windows 验收清单已更新，不再包含与透明窗口冲突的 Mica 要求。
7. 实现完成后暂停供用户审查，不执行 Git 写操作。
